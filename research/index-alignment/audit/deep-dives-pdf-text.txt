01 — Index Foundations: Typed Indices,
Registries, Lineage, and Scale Trees
Backs manuscript §§1.1, 2.1, 3.1–3.2, 3.6 and Appendix C.
1.1 The problem the index abstraction solves
A sparse language-model system does not produce text from a single undiﬀerentiated
computation. At each step it makes discrete selections: a top-k gate chooses experts
inside a layer (Shazeer et al., 2017; Fedus et al., 2022; Jiang et al., 2024); an
orchestrator chooses an agent (Wu et al., 2023; Fourney et al., 2024); a retriever
chooses passages (Lewis et al., 2020); a planner chooses a tool (Schick et al., 2023; Yao
et al., 2023); a memory manager chooses a path (Packer et al., 2023). Each selection is
an identiﬁer drawn from a ﬁnite set. Coleman (2026a, §3.1) named these identiﬁers
indices and observed that a large class of production failures is a mismatch between
indices rather than a defect of ﬂuency: the citation that names a document never
retrieved, the tool call that uses a deregistered version, the summary that silently drops
a committed fact.
The value of the abstraction is that indices are observable. Hidden activations are not
certiﬁable objects; an expert ID in a router log, a document hash in a retrieval record,
and a commit record in a ledger are. This ﬁnite veriﬁer requires an explicitly
represented, enumerable obligation universe. Typed indices supply one such
representation for the exposed trace; they are not a necessary condition for every
meaningful boolean proposition or every possible veriﬁer. Whether this abstraction
captures a task's relevant failures remains an empirical coverage question.
1.2 Why every index must be typed and versioned
Deﬁnition 1 writes an index as ι = (type, name, epoch, version). Each component removes
a speciﬁc ambiguity that otherwise breaks a checker.
Type. Coleman (2026a) already used a disjoint union 𝓘 _expert ∪ 𝓘 _agent ∪ 𝓘 _mem ∪ 𝓘 _tool ∪
𝓘 _doc. The continuation extends it with claim, correction, source, and obligation, because
those are the objects corrections and continuity act on. Disjointness matters
operationally: a string such as search can be a tool, an agent persona, and a memory
namespace at once. A checker that compares untyped names can certify that "the cited
search was active" when the active search was a tool and the cited one a document.
Typing converts that silent category error into a failed cast (⊥) in Deﬁnition 3.
Epoch. A registry changes. Tools are deprecated, experts are retrained, policies are
revised. The epoch names the registry state against which liveness and permission are
evaluated. Without it, Live(ι) is ill-posed: live when? Trace E in the manuscript (stale
tool authority) depends entirely on this ﬁeld — the approval was genuine under r7 and
obsolete under r8.

Version. The version distinguishes contents or interface of the resource itself. A
document revised from version 2 to 3 (Trace G) keeps its name; claims supported by
version 2 may be unsupported by version 3. Version is the hook by which a correction
ﬁnds its dependents.
The rule "an index name without a type is not a well-formed certiﬁcate ﬁeld" is
therefore a parsing rule with semantic consequences: it forces every downstream
predicate to operate on unambiguous objects.
1.3 Registry entries and the separation of liveness from
permission
A registry entry Reg(ι) = (type, capabilities, input_schema, output_schema, authority_scope,
validity_interval, digest) supports two predicates the manuscript keeps apart:
Live_k(ι): the entry exists at scale k, its validity interval covers the relevant logical
time, and its digest matches the observed artifact.
Permitted_k(ι, a): policy Π_k permits action a on that entry for the authenticated
principal.
The distinction is the content of Trace B. A registered, live, in-budget expert can be
activated for a task it is not permitted to perform. Registry membership answers "does
this thing exist and is it the thing I think it is?"; policy answers "may this principal use it
for this?". Conﬂating them creates an authorization failure when a tool's presence in
the tool list is treated as license to call it. No comparative prevalence claim is
established here. The digest ﬁeld closes a third gap — substitution — by binding the
name to the artifact actually executed.
The policy is declared an input to the audit, "not something inferred from successful
execution." This is a deliberate refusal of a tempting inference. A call that succeeded
shows that the environment accepted it; it does not show that it was permitted. Many
environments accept calls they should not.
1.4 Activation records and why gate weights are telemetry
Deﬁnition 2's activation record r = (ι, parent, gate, input_digest, output_digest,
principal, event_id) records the fact of selection. The manuscript states that "a nonzero
gate does not imply permission, authority, support, or correctness." The reason is
mechanistic. In a softmax gate p_i(x) = exp(h_i)/Σ_j exp(h_j) followed by top-k (Coleman
2026a, §3.1, following Shazeer et al. 2017), the gate value measures the router's
learned aﬀinity between an input and an expert. It is trained for loss reduction, often
with an auxiliary load-balancing term (Lepikhin et al., 2020; Fedus et al., 2022).
Nothing in that objective encodes authorization or factual support. A high gate on a
wrong expert and a low gate on the right one are both ordinary. Hence A_route never
reads gate magnitude as quality; gates enter only as telemetry and, where a budget is
declared, through Budget(r).

1.5 Morphisms and lineage: the pointer discipline generalized
Pointer Networks (Vinyals et al., 2015) make a model's output an index into its input,
which guarantees by construction that the output refers to something present.
Deﬁnition 3 generalizes that guarantee across stores. A typed morphism μ: 𝓘 _a → 𝓘 _b ∪
{⊥} records a legal cast — document to memory path, tool output to ledger subject. A
lineage for c is a witnessed path ι_0 → … → c with ι_0 in the visible activation history
R_{≤t}.
Three properties follow directly from the deﬁnition and are used throughout the
manuscript:
1. Existence is not lineage. "If no path exists, c is unaligned with the activation
history even when its display name is real in some registry." A citation to a real
document that was never activated in this run fails. This is the "index echo" falsiﬁer
(§11.9, item 8).
2. Lineage is not support. A path shows that evidence was visible, not that it entails
the claim. The generation predicate (deep dive 02 and §4.4) therefore adds Fidelity
separately.
3. Lineage is ﬁnite and checkable. Given a ﬁnite trace, deciding whether a
witnessed path exists is graph reachability, which is linear in nodes and edges. This
is the basis of the veriﬁcation bound in Proposition 10.
1.6 Content-bound receipts: what a hash does and does not
show
Deﬁnition 4 introduces the receipt R(u) = (digest, version, quoted_span, span_offset,
verifier_id, intake_event, vector_clock, scope). The key analytical point is the diﬀerence
between binding and reading. Given candidate byte strings, matching SHA-256 digests
provide an integrity check under the cryptographic assumptions. A party can copy a
digest without possessing the source bytes. Neither possession of a digest nor
computing a hash shows that a model read or understood the source, relied on it, or
was entitled to use it. Trusted evidence of a hash computation can support ﬁle access
by that computing component; a reported digest alone cannot.
An unpredictable quoted-span challenge can supply sampled evidence that the
responder can return content at the speciﬁed oﬀset under a declared threat model. A
guessed, memorized, cached or relayed answer must be accounted for; a successful
challenge does not prove historical reading, understanding or causal use. This is one
possible content-evidence mechanism, not a universal requirement for every veriﬁer. Its
strength also depends on the veriﬁer's independence. The manuscript's rule that
"independent veriﬁcation requires a veriﬁer outside the process capable of forging the
receipt" is the standard trust-boundary argument: if the same process chooses the
challenge, holds the key, and checks the answer, it can produce passing receipts for
content it never handled. Section 8.5 applies the same reasoning to in-process HMACs.
This distinction is the basis of the PROV-002 hash-only falsiﬁer and of mutation M03
(valid hash, wrong quoted span).

1.7 Scale trees: what "scale" means here
Deﬁnition 5 deﬁnes a ladder s_0 > … > s_M of partitions P_k, each reﬁning the previous
one: every child chunk has a unique parent containing it. Partition depth k increases
toward ﬁner chunks. The composition proof uses a separate lift index j, with Q_j
corresponding to P_{M-j}; increasing j moves from ﬁne base obligations to coarse
parents. Three choices in this deﬁnition carry the weight of later results.
Finiteness. M is ﬁnite and declared by the implementation. Every localization result in
§6 depends on ﬁnite enumeration; nothing is claimed about limits.
Reﬁnement as containment. Requiring C ⊆ parent(C) gives each ﬁne item exactly one
coarse ancestor. That is what makes the sticky case (deep dive 03) well deﬁned and
what makes failure localization a tree walk.
Scales are audit levels, not model scales. "Leaves represent the ﬁnest declared
units, not unknowable token-level neural semantics." A scale may be a routing layer, a
retrieval-to-claim stage, a tool boundary, a handoﬀ, or a chunk reﬁnement. The
induction in §6.2 is over these declared levels. It is not induction over parameter count,
training compute, or context length, and no result about those is implied. Keeping this
explicit prevents the most tempting misreading of "induction on scales."
The manuscript also notes that "no formula for M is imported from geometry." In Guth–
Wang–Zahl (2026) the scale chain ρ_k = δ^{k/M} is part of a proof; here depth is an
engineering budget.
1.8 Density observables and boolean stickiness
Deﬁnitions 6–7 introduce KT_k (maximum ratio of selected chunks in a window to the
data owner's expected count) and F_k(alpha) (maximum supported-mass share in a
declared family of short contiguous subspans). For each positive-mass chunk C, eligible
subspans satisfy 0 < length(V) ≤ alpha_k length(C), with 0 < alpha_k < 1. The family, length
convention and measure are declared inputs. Excluding the full chunk repairs the
original unrestricted maximum, which was identically 1 because V=C was eligible. These
computational analogues are not Katz–Tao or Frostman quantities. They can distinguish
selected distributions under their chosen windows, but useful thresholds and any
relationship to omitted evidence require independent evaluation.
STICKY_k requires fresh nesting and governing acknowledgments, with clustering caps
added only when the contract declares them applicable: NEST_OK_k ∧ ANCEST_OK_k ∧
optional([KT_k ≤ θ_KT] ∧ [F_k(alpha) ≤ θ_F]). Explicit inapplicability is required to omit the
caps. If a required observable's denominator, measure, expected count or eligible
window family is unavailable, including when no eligible windows or no positive-mass
chunks exist, its value is UNKNOWN. Missing required contract parameters or thresholds
yield NO_VERDICT. A cap comparison does not replace nesting or authority checks.

1.9 Events, happened-before, and slices
Deﬁnition 13's event tuple collects routing, proposals, commits, text, continuity state,
reads, writes, actor, authority evidence, lineage edges, and clocks into one record per
step, so all four predicate families read from a common trace. Deﬁnition 14 deﬁnes
happened-before as the smallest relation containing program order, send/receive,
intake/receipt, proposal/commit, and correction/dependency edges — Lamport's (1978)
relation specialized to the event kinds that matter for certiﬁcation. Wall clocks alone
are insuﬀicient across distributed components because clock skew can invert causal
order; explicit edges cannot.
Deﬁnition 16's slice completeness rule — a predicate whose required inputs are absent
returns UNKNOWN — is what prevents a truncated log from being certiﬁed. It is the
foundation of every non-vacuity argument in the paper.
1.10 Summary of what this layer establishes
The foundation layer makes three things true by construction: every object a predicate
inspects is unambiguous (typed, epoched, versioned); every relationship a predicate
relies on is an explicit, witnessed edge in a ﬁnite graph; and every absent input
produces a named non-pass rather than a default. Those three properties are what
allow the later sections to state results about boolean outcomes that are provable
rather than aspirational.

02 — Boolean Evidence Semantics: Why
Alignment Can Be Boolean Without
Pretending to Know
Backs manuscript §§1.1, 4.1, 4.6–4.9, 5.1, 6.1, 6.6, Appendix A.1 and B.1–B.2.
2.1 The central claim, stated exactly
The manuscript's thesis is that alignment, in a speciﬁc declared sense, "can be treated
as a boolean kind of problem." The precise content is a separation of two layers:
1. Semantic layer. For an obligation q, a ﬁxed history H_q, a policy snapshot Π(q), and
a speciﬁcation Spec_k, the authorization predicate A_q and the compliance predicate
C_q each take a value in {0,1}. Once the speciﬁcation and history are ﬁxed, either
the history satisﬁes the speciﬁcation or it does not. This is ordinary bivalence of a
well-deﬁned proposition.
2. Evidence layer. A monitor observing partial evidence returns a verdict V ∈ {T, F,
U}, reﬁned operationally into PASS, FAIL, UNKNOWN, and NO_VERDICT. The monitor may not
know the semantic value.
The release decision is then a third object: a bit b(P) = 1 iﬀ Ev(P) = PASS. That bit is
boolean by design. The thesis is not that knowledge is always available; it is that the
question is boolean and the control is boolean, while the evidence state is honestly
three-valued. Deep confusion about "boolean alignment" usually comes from collapsing
those three layers.
2.2 Why this monitor retains an inconclusive outcome
Suppose a monitor were required to answer only true or false. Given incomplete
evidence about obligation q, it must either answer T — and be unsound whenever the
missing evidence would have shown a violation — or answer F — and be unsound
whenever the missing evidence would have shown compliance. The manuscript's
"Unknown is not true" counterexample (§6.11) makes this concrete: three required
operations, two observed and passing. Reporting "2/2 passed" silently changes the
denominator. Reporting F asserts a violation nobody observed. Within the chosen total-
response interface, U is the sound response when neither truth value is justiﬁed. An
abstaining interface or a richer evidence algebra could also preserve soundness;
exactly three values are not universally forced.
This is the same structure runtime veriﬁcation faces. Bauer, Leucker, and Schallhart
(2011) deﬁne three-valued LTL semantics for ﬁnite trace preﬁxes precisely because a
ﬁnite observation of an unﬁnished execution may neither satisfy nor violate a property;
an inconclusive outcome preserves soundness in their monitor design. The index-

2.3 Strong Kleene conjunction and Proposition 1
The manuscript aggregates verdicts with strong Kleene conjunction: F dominates, T is
the identity, and otherwise the result is U. Proposition 1 proves that if each local verdict
is sound (V_q = T ⇒ P_q = 1, V_q = F ⇒ P_q = 0), the aggregate is sound for the conjunction.
The proof is short, but each case does work:
Aggregate T. Strong Kleene yields T only if every input is T. Soundness gives every
P_q = 1, so the conjunction is 1.
Aggregate F. Some input is F, so some P_q = 0, so the conjunction is 0 — regardless
of unknowns elsewhere. This is why an observed failure can be reported even when
other evidence is missing; Trace C relies on it.
Aggregate U. No input is F and some is U. The semantic conjunction might be 0 or
1. The monitor correctly asserts neither.
Two consequences matter. First, soundness is inherited, not created: "it does not make
an unsound checker sound." A support model that labels contradictions as support
breaks the guarantee at its source, which is why deep dive 08 insists on independent
labels. Second, strong Kleene conjunction retains a decisive observed F even alongside
U. Weak Kleene conjunction can remain sound but is less informative in that case
because it returns U. A diﬀerent rule that relabels unknown evidence as observed
falsehood can be unsound: an aggregate F would no longer imply an actual violation.
Mapping unknown to a release bit of zero is instead an allowed control choice when the
evidence reason remains visible.

2.5 Non-compensation
Coleman (2026a, Deﬁnition 2) deﬁned the alignment deﬁcit Δ_t = λ_1 d_route + λ_2 d_led
+ λ_3 d_gen + λ_4 (1 − Cont). Weighted scores can summarize defects and support
optimization; diﬀerentiability requires diﬀerentiable constituent functions on an
appropriate domain. Whether release compensates for a failed required condition
depends on the score ranges, weights and release threshold, not on scalar
representation alone. For example, if b_i∈{0,1}, w_i>0 and D=Σ_i w_i(1-b_i), releasing
exactly when D=0 is equivalent to conjunction. No term can compensate for a positive
deﬁcit because every term is nonnegative.
The manuscript requires a noncompensatory release rule, expressed as conjunction; an
equivalent scalar encoding is permitted. §4.9 states the formal property: replacing any
required True by False makes A(k) false regardless of other values. A boolean rule that is
true exactly when every required input is true is, by deﬁnition, conjunction; any rule
that can return true while some required input is false is compensatory. The same
discipline appears in Coleman (2026b) for SAVER and SIUS grain vectors ("no weighted
average compensates a failed grain"), and the manuscript adopts it as the operational
meaning of "boolean alignment": named necessary conditions.
Non-compensation is a design choice with costs. A conjunctive release rule may block
outputs that a compensatory weighted rule would pass; an equivalent zero-deﬁcit scalar
rule makes the same decisions as conjunction. The partial-release machinery (deep dive
06) exists to recover utility without reintroducing compensation: rather than averaging
a failure away, it isolates the failure and releases what does not depend on it.
2.6 Composite deﬁnitions: A(k), ALIGNED_k, ALIGNED(T)
The manuscript deﬁnes three related conjunctions and keeps them distinct:
A(k) := A_route(k) ∧ A_ledger(k) ∧ A_gen(k) ∧ A_cont(k) — full per-scale alignment.
ALIGNED_k := COV_k ∧ ORDER_k ∧ CORR_k (∧ STICKY_k) — a narrower
coverage/order/correction diagnostic contributed by the Kakeyalogic seat packet.
ALIGNED(T) := ∀k, A(k) — global alignment across scales.
ALIGNED_k is not an alias of A(k). A trace can have complete coverage, valid order, and
closed corrections and still fail Fidelity (Trace C). Naming the narrow diagnostic
separately prevents a coverage dashboard from being read as an alignment certiﬁcate.
Likewise ALIGNED(T) is not CERTIFIED: certiﬁcation adds release authority and non-vacuity.

2.7 Non-vacuity and the empty denominator
Any universally quantiﬁed predicate over an empty set is true. A checker that ﬁnds no
required routes, no claims, and no obligations will therefore "pass" vacuously. Deﬁnition
27 lists the vacuous cases — empty required set, unknown denominator, empty route or
claim sets despite required work, skipped checks reported as passes — and Proposition
6 shows that if NONVACUOUS is a required conjunct, a non-PASS value forces the release bit
to zero.
The companion rule EvidenceCoverage = |Q_sound|/|Q_req|, with n/a when Q_req = ∅, closes
the reporting loophole. Reporting 100% coverage on an empty universe is the
denominator version of the same error. The manuscript's insistence that the obligation
universe be independently established (§5.5) — by a speciﬁcation manifest rather than
by counting observed records — follows: the denominator cannot come from the same
evidence it is meant to audit. The 10-agent-team notes ﬂagged exactly this circularity in
an early version of Trace A ("all ﬁve obligations present" includes itself); the manuscript
now states that the ﬁfth obligation's completeness comes from the manifest.
2.8 SKIPPED is not PASS
§4.7 adds a ﬁfth operational marker: when an earlier failure makes a later check unsafe
to run, the later check is SKIPPED. This prevents a common reporting artifact in which
tests that never ran appear green. It also preserves the rest of the evidence: a
certiﬁcate reports the ﬁrst failure and all later observed failures, so an early failure
does not hide independent later defects.
2.9 Boolean predicates are only as good as their
speciﬁcations
The boolean framing makes one limitation sharper rather than softer. A semantic
predicate is boolean only relative to a ﬁxed speciﬁcation. If the speciﬁcation is wrong, a
correct certiﬁcate certiﬁes the wrong thing. §12.6 lists "semantic booleanization error"
— forcing a graded or contested judgment into PASS/FAIL — as a failure mode, with the
defense of retaining CONTESTED and UNKNOWN labels and booleanizing only the release
control. Deep dive 09 connects this to Grill (2024) on the politics of testing
infrastructure: who writes the speciﬁcation is a governance question the certiﬁcate
cannot answer.
2.10 What this layer establishes
Booleanity in this paper is achieved by three moves: ﬁx the speciﬁcation so the
semantic question has a truth value; report monitor knowledge in three values so that
soundness is preserved under incomplete evidence; and project to a PASS-only bit at
the control boundary so that release is conservative without mislabeling unknowns as

03 — Scale Reﬁnement and Composition:
Induction on Declared Scales
Backs manuscript §§1.2, 2.2, 5.1–5.9, 6.2, 6.8–6.9, 6.11, Traces A and K.
3.1 What "induction on scales" borrows and what it does not
In three-dimensional Kakeya geometry, Wang and Zahl (2025) prove that Kakeya sets in
ℝ³ have full Minkowski and Hausdorﬀ dimension, and Guth, Wang, and Zahl (2026) give
a streamlined proof. Coleman (2026b, §2.4) reads their architecture as an order of
work: control the sticky conﬁguration, then the non-sticky sparse two-scale case, then
factor via slabs and planks, then account for the residual, and only then state the
general result. That order is the part this paper borrows.
What it does not borrow is any inequality. The geometric arguments establish
asymptotic volume and dimension bounds stated with ≲-type inequalities and losses that
are acceptable in the limit. An audit needs a threshold comparison at a ﬁnite scale. §1.2
of the manuscript says the analogy "changes how we organize an audit; it does not
supply the audit's semantic predicates or prove their validity." The Kakeyalogic seat
packet makes the same point: boolean, traceable induction on scales is not a
consequence of Wang–Zahl or Guth–Wang–Zahl. Everything proved in this deep dive is
proved from ﬁnite combinatorics and the stated hypotheses.
3.2 The obligation universe
At each lift level j the manuscript requires an independently speciﬁed ﬁnite obligation
universe Q_j (§5.1), corresponding to partition P_{M-j}. Partition depth k increases
toward ﬁner chunks; lift index j increases toward coarser parents. An obligation can be
local — one activation, one retrieval, one commit — or a cross-operation invariant such
as a shared budget or a correction frontier. Cross-operation obligations are the entire
reason composition is nontrivial; deep dive 03.7 shows what fails without them.
For each obligation q the paper uses two predicates, authorization A_q and compliance
C_q, because they answer diﬀerent questions: "an authorized write can violate a
schema; a well-formed retrieved instruction can be unauthorized." Keeping them
separate prevents a single combined "ok" bit from hiding which question failed.
3.3 The four composition conditions
Proposition 2 lifts sound local certiﬁcates to sound global ones under four conditions.
The proof uses all four as suﬀicient premises. They are not claimed to be a minimal
axiom set or universally necessary for every alternative architecture. Their failure
permits recognizable counterexamples.

R — Evidence-preserving reﬁnement. For each parent obligation q there is a child
set D_j(q) with ( ⋀ _{r∈D_j(q)} (A_r ∧ C_r)) ⇒ (A_q ∧ C_q). This is a reﬁnement mapping in
the spirit of Abadi and Lamport (1991): it states how a coarse speciﬁcation is
implemented by ﬁner steps. The manuscript's R is narrower than their existence
theorem; it is a certiﬁcate-speciﬁc implication that must be witnessed. Renaming an
index or matching a label does not supply it.
C — Complete obligation coverage. D_j(q) accounts for every operation, eﬀect, and
cross-operation premise relevant to q, and Q_j is closed under work generated during
the trace — retries, callbacks, dynamically spawned tasks. Without C, the induction
proves the parent from an incomplete set of premises.
N — Noninterference. Operations outside the certiﬁed set cannot alter state on which
authorization, compliance, evidence, or reﬁnement depends. This is the noninterference
idea of Goguen and Meseguer (1982) applied to certiﬁcate premises: low-integrity
content must not inﬂuence high-integrity decisions. Concretely, retrieved text cannot
rewrite policy, routers cannot commit, generators cannot self-accept.
K — Correction-aware concurrency and freshness. The contract states
operation/transaction boundaries and its required real-time freshness guarantee.
Single-object operations may use linearizability, but individually linearizable ﬁeld reads
can straddle an update. Cross-ﬁeld reads require a joint atomic snapshot, a justiﬁed
strictly serializable transaction, or validated version protocol across all relevant ﬁelds,
with appropriate eﬀect-boundary validation. Ordinary serializability is not equivalent to
either guarantee (Herlihy and Wing, 1990, §3.3). Relevant reads use the speciﬁed
snapshot semantics; every causally preceding correction is included; versions are valid
at eﬀect boundaries; accepted corrections invalidate dependents before promotion;
concurrent conﬂicts are resolved; replayed approvals do not create fresh authority.

3.6 Sticky, non-sticky, and the band
The sticky case (§5.3) is the regime in which each ﬁne item has one visible coarse
parent, authority and correction scope are shared, all versions agree with the snapshot,
and no unlisted channel aﬀects the parent. In that regime the parent check depends
only on its declared children and the certiﬁcate is small: parent identity, children,
receipts, correction acknowledgments, reﬁnement witness.
The manuscript deﬁnes a concrete stable-custody nesting from the Riemann-probe
packet. For every applicable ancestor a of grain g, ANCEST_OK_k requires an
acknowledgment (a.id, c_id, c_ver) naming the currently governing correction in a's
own registry. NEST_OK_k requires fresh parent edges and content hashes. The paper
explicitly declines a global comparison correction_version(parent) ≤
correction_version(child) because counters from diﬀerent registries are incomparable —
a subtle point: version numbers are only ordered within the registry that issues them.
The non-sticky band is the set of grains, claims, and transitions for which nesting
fails. The geometric reading in Coleman (2026b) is that coarse tubes can overlap
heavily while ﬁne tubes inside them are sparse; the systems reading is that ancestry,
authority, or correction scope diverge across children. The discipline imported is factor
only the band: repair the region that left the sticky regime rather than restarting the
whole trace or averaging its failure into global telemetry. Deep dive 05 gives the
aﬀected-closure algorithm that does this.

5.1 Why corrections are the hard case
A system that never changes its mind is easy to certify. Real systems receive
corrections: a source is revised, a policy revoked, a user retracts an instruction, a tool
is deprecated. Each correction makes some earlier certiﬁcates obsolete, and the
diﬀiculty is knowing which. Too narrow an invalidation lets stale conclusions survive;
too broad an invalidation discards everything and destroys utility. The manuscript's
answer is to treat a correction as a scoped graph operation with explicit authority, and
to compute its consequences by reachability.
5.2 The correction object
Deﬁnition 15: c = (target, issuer, authority_evidence, scope, applicability, lineage, nonce,
tag, timestamp). Each ﬁeld has one job.
target is the seed in the dependency graph.

authenticated authority over the target and scope.

from silently rewriting another (mutation M15).
nonce and tag support integrity and replay detection.
The manuscript states that "cryptography does not make the issuer correct." A validly

response to conformity ﬁndings in multi-agent settings (Weng, Chen, and Wang, 2025)
— models can converge on a group answer whether or not it is correct.

5.4 The stale-concurrent-approval example
§6.11 gives the example that motivates condition K. Approval a authorizes tool:t17

Read componentwise: VC(a) ≤ VC(o) in every coordinate and diﬀers, so a → o. VC(c) and

the frontier is known, current authorization is U: the approval might still be valid. After
a complete history shows that current policy requires r8 validity and r8 revokes the tool,

manuscript draws — "signed and fresh are separate" — is the precise distinction

5.5 Condition K in six parts
Condition K (§5.7) is the formal summary of what freshness requires:
1. The contract declares operation/transaction boundaries and the required real-time
freshness property. Linearizability applies to single-object operations; strict
serializability can supply real-time transaction order for multi-operation
transactions. Ordinary serializability alone is insuﬀicient for that order and is not
equivalent to linearizability (Herlihy and Wing, 1990, §3.3). Individually
linearizable ﬁeld reads do not ensure a joint snapshot: use a joint atomic snapshot,
a justiﬁed strictly serializable transaction, or a validated version protocol across all
relevant ﬁelds. Policy-dependent eﬀects require an appropriate atomic admission
or revalidation boundary.
2. Every causally preceding correction is included — and concurrent corrections are
not fabricated into dependencies. Overstating dependencies is also an error: it can
invalidate certiﬁcates that were never aﬀected.
3. Versions remain valid at eﬀect boundaries or are revalidated. Time-of-check/time-
of-use gaps are the classic violation.
4. Accepted corrections transitively invalidate dependents before promotion.
5. Conﬂicting concurrent operations are ordered or explicitly resolved.

5.6 Aﬀected closure
Given seeds Z — failing or corrected nodes — the manuscript computes Aff = Reach_G(Z),
the set of all nodes reachable from the seeds in the dependency graph, across indices,
scales, claims, ledger projections, and pending actions (§5.8). Every node in Aff is
marked stale or quarantined with the appropriate status, history is preserved, evidence
outside Aff is retained if N holds and its freshness is valid, repairs are made along
aﬀected edges, and the entire closure is rechecked — not only the seed.
Rechecking the whole closure is the critical step. A common incremental-repair bug is
to ﬁx the seed and assume downstream results update automatically. If a summary was
generated from a claim that was generated from a corrected document, ﬁxing the
document does not ﬁx the summary; the summary must be regenerated or quarantined.
Mutation M14 (one aﬀected descendant omitted) targets exactly this.
Computing Aff is linear in the graph: breadth- or depth-ﬁrst search visits each node and
edge once. Appendix B.4 gives the pseudocode, and Proposition 10's bound includes
one shared traversal for the union of closures.
5.7 Proposition 7: what stays valid
Proposition 7 states the complementary guarantee. If output set O satisﬁes Deps(O) ∩ Aff
= ∅, N holds, evidence versions for O are stable, and the dependency graph is complete
for the release scope, then a correction conﬁned to Z and its outgoing dependencies
does not change the predicates certiﬁed for O.
The proof is reachability plus isolation: no dependency path from Z reaches O's
dependencies, N excludes unmodeled inﬂuence, and stable versions keep inputs ﬁxed.
Each hypothesis has a practical failure. An incomplete dependency graph misses an
edge — for example a shared cache or a hidden context window (mutation M31). A
failure of N allows a correction to inﬂuence O through a side channel. Unstable versions
mean O's evidence changed for an unrelated reason. When any is uncertain,
unaﬀectedness is UNKNOWN, and partial release is not certiﬁed.
The manuscript adds a limit that graph semantics cannot overcome: "previously emitted
unretractable copies cannot be recalled by graph invalidation." Invalidation governs
future promotion. It does not retrieve an email already sent.

6.1 Three things that are easy to confuse
A system can hold an object, be entitled to act on it, and release conclusions drawn
from it. These are three separate properties. Coleman (2026b, §6.3) states the ﬁrst
separation as "held = relevant + retained ≠ truth": keeping something for evaluation is
not endorsing it. The L²_C authority rule (Coleman 2026b, §7.2) states the second:
detection of source, authority, intent, and harm precedes incorporation, and untrusted
text may be read as content without becoming an instruction. This deep dive explains
how the continuation turns those principles into a release contract.
6.2 Custody is not truth
In Coleman (2026b), the HELD predicate requires an object to be typed, grounded,
evidence-exposed, correction-preserved, and status-visible. Every clause concerns how
the object is kept, none whether it is true. The continuation preserves that property: a
grain record (§5.2) carries a content hash, status, authority stamp, dependencies, and
governing acknowledgments, and the manuscript states that the hash "is not a read
receipt, semantic support, freshness, or permission." A perfectly custodied false claim is
still false. Custody is what makes later correction possible — you cannot invalidate what
you did not keep — which is why NOSILENT requires superseded records to remain
queryable.
6.3 Authority: Act = S · H · U and Act = 0 ⇏ Stop
Deﬁnition 9 adopts the three-factor authority gate: authenticated source authority S,
hierarchy validity H, authorized user intent U. All three must be 1 for Act = 1. Two
consequences are built into the deﬁnition.
S = 0 ⇒ Act = 0. Content from a source without authority cannot authorize an action no
matter how it is phrased. This is a proposed structural constraint against instruction
injection, whose protection depends on complete mediation and enforcement: Trace L's
document saying "make router an approver" has a valid content receipt and no
authority. The manuscript's "found content is not an instruction" example states the
verdict: F if evidence establishes no authority, U if authority evidence is incomplete,
never T from retrieval alone.
Act = 0 ⇏ Stop. Denying an action is not the same as halting the system. A privileged tool
call can be refused while an informational response explaining the refusal is still
produced. Coleman (2026b) states this as detection without resistance: L²_C "does not
resist instruction-shaped content," it declines to incorporate unauthorized instructions

and proceeds toward an authorized outcome. The continuation uses the rule to justify
partial release (§6.6 below) and is explicit that it "does not override a separate policy
requiring complete suppression."
6.4 Selection, gate verdict, execution, eﬀect
AIce's contribution adds a four-way distinction that the manuscript adopts in §§6.8, 7.2,
and 10.4: selected_action, gate_verdict, executed_action, observed_effect. Each can diverge
from the others.
A gate can reject a selection that an advisory executor runs anyway. AIce's shipped
simulator was advisory in exactly this way.
An enforcing wrapper can block correctly and still reject legitimate work — AIce's
E2 false stop.
A blocked action can still have produced partial logs or externally visible eﬀects
before the block.
The manuscript draws the consequence: "a correct veriﬁer can be attached to a broken
executor." Certiﬁcates about detection say nothing about enforcement unless
enforcement is separately recorded and checked. Mutation M27 (gate rejects but tool
executes) is classiﬁed as EXECUTION_ERROR, distinct from detection — a distinction
formalized in deep dive 08.
6.5 Structural readiness and full release
§5.10 deﬁnes two levels of promotion.

declared external assessor.

rule that four-valued evidence maps to PASS-only bits, with missing evidence blocking

7.1 Why localization is the practical payoﬀ

7.2 FIRST_FAIL and FIRST_NONPASS
Deﬁnition 24 declares a partition-depth order π=(k_0,…,k_M) and uses FIRST_FAIL(T;π) :=
min{i : A(k_i) = False}, recording both order position and partition depth. In the ﬁnest-
ﬁrst traces, i=j and k_i=M-j. Proposition 3: on a ﬁnite total scale order, if the failed set is
nonempty, the minimum exists and is unique; with a declared sub-conjunct order, the
reported failing predicate is unique too. The proof is the well-ordering of ﬁnite totally
ordered sets.
The manuscript reports a second location, FIRST_NONPASS, the least scale with an UNKNOWN
or NO_VERDICT outcome preceded only by passes. The two are reported separately
because they mean diﬀerent things. If scale 2 is UNKNOWN and scale 4 is FAIL, the observed
failure is at 4, but the earliest point where certiﬁcation became impossible is 2, and the
real defect may be there. Overwriting either location with the other would lose
information.
The manuscript also limits the claim: FIRST_FAIL is "the earliest known failed declared
lift, not a metaphysical origin." Several defects can produce the same failed predicate,
and the true cause may lie outside the instrumented trace. Trace N makes this
concrete: the omission surfaces at the handoﬀ scale even if the compressor that caused
it is upstream and unrepresented.

has y ≺ x}, the set of minimal failures. Proposition 4: in a ﬁnite acyclic order, every
nonempty F has at least one minimal element, and every failure has a minimal failed
ancestor. The proof is descent along strict predecessors: acyclicity forbids repetition,

7.4 Computability (Proposition 5)
If each checker terminates on its ﬁnite slice, reachability is over a ﬁnite graph, and
thresholds are present, the trace, frontier, and aﬀected closure are computable in ﬁnite
time. The proposition is deliberately weak: it is a termination guarantee, not a cost
bound, and it excludes semantic discovery. Its practical point is the converse — when a
checker does not terminate (an LLM assessor times out), that is an execution status,
not a semantic failure. Deep dive 08 develops the execution taxonomy.
7.5 Two-ends support and directional coverage
Two predicates detect a failure that counting receipts misses: concentration.
TWO_ENDS(q) (Deﬁnition 25) requires that no admissible window shorter than ε|S| contain
more than a θ_2E share of a claim's declared support. A claim that is "supported by" a
300-page source but draws all its support from one paragraph may be correct, but it
has not engaged the source as a whole; where the contract requires distributed
evidence, that should be visible. The vocabulary is borrowed from the two-ends
condition in the restriction literature (Wang and Wu, 2024), where it excludes
conﬁgurations whose mass concentrates in a short piece of a tube; here it is a caller-
parameterized audit check, not a theorem.
Directional coverage (Deﬁnition 17) requires that each declared direction of relevance
— evidence class, obligation, tenant partition — retain a distinguishable lineage at each
scale. It is the systems analog of the light-rule posture in Coleman (2026b, §3),
contributed through the L seat: every required direction through the custody center
remains represented. The manuscript bounds it twice: directions must be declared (no
claim to capture all semantic directions), and coverage overlap does not imply
authority. High coverage in one class cannot repair an omitted class.

8.1 What a falsiﬁable certiﬁcate design looks like

8.3 Detection requires a baseline and an attributable failure
The most consequential methodological rule in the evaluation section is that "a nonzero
exit status alone never counts as detection" (§11.6). It comes from a concrete hazard
reported by the 10-agent team's review of an open-addressing probe: same-author
mutation scripts that count any nonzero exit as a "killed" mutant. An import error, an
unrelated assertion, or a timeout then counts as successful detection, inﬂating the kill
rate with infrastructure failures.
The manuscript's taxonomy separates ﬁve outcomes:
CLEAN_PASS — the unmodiﬁed baseline passes named checks under the same
conﬁguration. Without it, no comparison is valid.
DETECTED — the variant runs far enough to evaluate the intended property and a
predeclared named check fails for the intended reason.
UNDETECTED — a valid run completes without relevant detection.
HARNESS_ERROR — the intended check could not be evaluated: import failure,
malformed harness, unrelated exception, timeout.
EXECUTION_ERROR — enforcement or environment fails even though detection
is valid.
Trace J demonstrates all of them on one conﬁguration. The team notes used

harmonizes them by putting them on diﬀerent axes — evaluation infrastructure versus
enforcement — so a single run can be DETECTED on the detection axis and EXECUTION_ERROR

8.4 Labels must be independent of the monitor
§11.2 requires that ground truth come from independently constructed speciﬁcations,
hand-audited synthetic traces, or injected faults with known mechanisms: "the
monitor's own output cannot supply its labels." This is the evaluation analogue of the
independent-veriﬁer rule. Three bodies of work motivate the speciﬁc protocol.
Human annotation discipline. AIS (Rashkin et al., 2023) and FABLES (Kim et al.,
2024) build attribution and faithfulness labels through structured human annotation,
and FABLES speciﬁcally annotates omissions in long summaries. The manuscript adopts
claim-level sampling and omission checks from that discipline.
Independence of judges. Sycophancy research (Sharma et al., 2024) shows models
adjusting answers toward perceived user preferences, and BenchForm (Weng, Chen,
and Wang, 2025) shows conformity to group answers. The protocol therefore collects
human ratings independently before discussion and treats agreement between model
assessors as non-independent evidence: separate answers from models with shared
training data and rubrics are correlated.
Criteria drift. EvalGen (Shankar et al., 2024) found that users reﬁne their evaluation
criteria while grading outputs. The protocol does not deny drift; it versions it.

8.8 Cost of veriﬁcation
Proposition 10 bounds veriﬁcation of a supplied restricted certiﬁcate at O(n + |E| + cB +

the restrictions are stated so that repeated per-claim or per-seed traversals, if an
implementation needs them, are charged separately rather than hidden.
The bound is about veriﬁcation, and §10.4 separates four costs that are often conﬂated:
search (ﬁnding routes, evidence, repairs), veriﬁcation (checking the witness),
enforcement (blocking execution), and observed eﬀect (what happened). Cheap
veriﬁcation does not imply cheap search. The P-NP seat's non-claims D1–D9 make the
boundary explicit: no reduction is given in either direction, no hardness or membership
claim is made for general index alignment, and polynomial veriﬁcation of a supplied
witness does not classify the search problem.

staged veriﬁcation to reduce cost; VeriLA (Sung, Kim, and Zhang, 2025) motivates
explicit, human-centered agent failure criteria. The protocol adopts the cost-reporting
discipline and requires that any selection policy itself be evaluated for missed
violations. The Grok Bot packet's rule that veriﬁcation spending should be incurred
where it can change the answer is the operational form.

9.9 Position of this work
The proposed contribution is the particular integration of four predicate families,
witness paths, correction handling and partial-release decisions for exposed sparse-
system indices. Noncompensatory release can be encoded as conjunction or an
equivalent scalar rule. The construction applies established reﬁnement,
noninterference and monitoring ideas under stated assumptions; it does not establish a
deployed checker or empirical advantage. Its geometric vocabulary supplies an
organizational analogy. Positioning against proof-carrying code and agent-action
certiﬁcates is necessary before making broader novelty claims.
